# 8bit Music Converter

mp4 (や mp3 / wav / m4a) か **YouTube の URL** を入れると、その曲を **ファミコン風の 8bit チップチューン** に作り直してダウンロードできるローカル Web アプリです。

元の音声にエフェクトを掛けるのではなく、曲を「耳コピ」してファミコンの 4 チャンネル
(矩形波 ×2 / 三角波 / ノイズ) で演奏し直す方式なので、本当にゲーム音楽っぽいピコピコ感が出ます。

## 使い方

```sh
./setup.sh      # 初回だけ (Python 3.12 の仮想環境を作って依存を入れる。数分かかります)
./run.sh        # サーバー起動 → http://localhost:35607 をブラウザで開く  (PORT=xxxx ./run.sh で変更可)
```

ブラウザ画面に mp4 をドロップするか YouTube の URL を貼り付けて「8bit に変換する」を押すと、変換後に試聴プレーヤーとダウンロードボタンが出ます。

コマンドラインでも使えます:

```sh
.venv/bin/python convert.py 曲.mp4              # → 曲_8bit.wav
.venv/bin/python convert.py 曲.mp4 --mp3 --duty 0.25 --arp-speed 2
.venv/bin/python convert.py "https://www.youtube.com/watch?v=XXXX"   # → <動画タイトル>_8bit.wav
.venv/bin/python convert.py 曲.mp4 --title "ヴァンパイア DECO*27"   # 曲名で Songle と照合 (メロディの精度が大きく上がる)
.venv/bin/python convert.py 曲.mp4 --midi        # → 曲_8bit.mid (採譜結果)
.venv/bin/python convert.py 曲_8bit.mid          # 直した MIDI をそのまま 8bit 演奏
.venv/bin/python convert.py 曲.mp4 --sensitivity 0.6 --tempo-mult 2 --octave 1 --no-fill
```

ポートは 35607 (16 進で 8B17 = "8BIT") にしてあります。他と被る場合は `PORT=12345 ./run.sh` のように変えられます。

## 処理時間 (Web アプリは 1 曲を最長 3 分で返します)

Web アプリ (`./run.sh`) は、変換を 1 つずつ順番に、別プロセスで実行します (`chiptune/jobrun.py`)。
- 時間が足りなくなりそうなら重い任意の処理 (ハモリの上の声の選び直し、曲名での照合) を省き、歌の分離が間に合わない見込みなら
  速いモード (basic-pitch) で採譜する (`chiptune/budget.py`)
- それでも 2 分半を過ぎたら止めて、取得済みの音声から速いモード (3 分の曲で 15 秒ほど) で作り直す。1 曲あたり 3 分弱で必ず返す
- 同時に 2 つ変換すると GPU (MPS) を使う歌の分離でプロセスごと落ちていたので、2 曲目は 1 曲目が終わるまで待つ (画面に「待っています」と出る)
- YouTube・Songle・モデルの重みの取得には待ち時間の上限を付けている

上限は環境変数 `CHIPTUNE_TOTAL_LIMIT` (既定 175 秒) と `CHIPTUNE_MAIN_LIMIT` (既定 145 秒) で変えられます。CLI には上限はありません。

## オプション

| 項目 | 説明 |
| --- | --- |
| 採譜モード | `auto` は使える中で最良のモード (ボーカル分離 > 高精度 > 軽量) を選ぶ |
| メロディの音色 | 矩形波のデューティ比 50% / 25% / 12.5% |
| コードのアルペジオ | 検出したコードを 16 分 (または 32 分) で回すお馴染みの伴奏 |
| 三角波ベース / ノイズドラム | チャンネルごとの ON/OFF |
| 8bit 量子化 | 出力を 8bit 相当に丸めてザラつきを足す |
| メロディにエコー / オクターブ | 8 分音符遅れのエコー (歌の細かい動きが二重に聞こえるので既定 OFF) と、メロディのオクターブ移動 |
| 歌の拾いやすさ | 分離モードで歌と判定する確信度のしきい値 (上げると拾いやすく、誤検出も増える) |
| テンポ | ビート検出が実際の半分になった速い曲は「倍にする」 (自動判定もあり) |
| 間奏をリード楽器で埋める | 歌が 2 小節以上無い区間を伴奏の主旋律で埋めるか (誤った音が出やすいので既定 OFF) |
| 調に合わない音を補正 | 推定した調から外れる短い音を半音寄せる |
| リズムを格子に整える | メロディの始まり・長さを 32 分音符の格子に量子化し、1 セルの揺れの吸収・オクターブ補正・子音による短い隙間 (2 セル未満) の補完・拍頭のアクセント付けを行う。それ以上の隙間は休符として残す (既定 ON) |
| 歌の無いイントロを省く | 最初の歌の 1 拍前から出力を始める (既定 ON)。歌の無いイントロで主旋律を捏造しない |
| 出力形式 MIDI | 採譜結果を MIDI で出す。DAW で直した .mid をそのまま入力に戻すと、その通りに演奏する |

## YouTube の URL を使うと Songle / TextAlive の情報を使います

入力が YouTube の URL で、その曲が [Songle](https://songle.jp) に登録されている場合 (マジカルミライの曲は概ね登録済み)、
- **歌詞の文字ごとの発声タイミング** (TextAlive で使われている人手修正済みのデータ) と **拍** を使い、
  「楽譜モデル + F0 モデル」(Nishikimi, Nakamura, Goto ら, ISMIR 2017 / IEEE TASLP 2020 の考え方) でメロディを推定します
  (`chiptune/score_model.py`)。歌の f0 を規則で刻むのではなく、
  - 楽譜モデル: 調 (音階) に沿った音高の事前、音程の事前 (小さい音程ほど確からしい)、拍節格子 (Songle の拍から 32 分) 上の
    音の始まり (拍頭 > 8 分裏 > 16 分裏)、音価の分布、歌詞の文字境界 (文字の頭で音を切り直し、文字の途中では切らない)
  - F0 モデル: 音符列から歌の f0 が生成される過程を Cauchy 分布で表す (ビブラート・しゃくりに頑健)。音の頭の移行区間は
    前後の音高の混合として扱う
  を合わせた確率モデルの下で、最も確からしい音符列を半マルコフ Viterbi で一括して決めます。「隣のキーを押したような」半音ずれや
  調外れの音が規則ベースより大きく減ります (グリーンライツ: 調外 33 → 9 音、外れ音 0.4%)。
  推定後に、分離の残渣によるごみ音を落とし、歌のフレーズに従って音をつなぎます (f0 が続く間だけ伸ばす)。
  文字の始まりは子音の頭なので、音高が変わる文字では f0 が前後の音高の中間を横切る時刻に音の頭を移します。
  伴奏の格子 (テンポ・16 分セル・小節頭) も Songle の拍から作り、メロディと同じ格子に乗せます。

- **自己検証と修正の繰り返し** (`chiptune/verify.py`): 採譜した音符列を歌の f0 と照合し、
  「外れ」(音の中央 50% の f0 が音符の高さから 1 半音超ずれ、かつその高さが音の中のどこにも歌われていない音)、
  「半音外れ」(音の中央 50% の歌がはっきり隣の半音に留まっているのに音符がずれている音。「隣のキーを押した」誤り) と
  「併合」(1 音の中に別の高さの安定区間がある音) を見つけて直し、外れが 0.1% 以内になるまで最大 5 回繰り返します。
  何回修正したか、目標に達したかは UI の結果欄 (「自己検証 OK / NG — 修正 N 回」) と CLI のログに表示され、
  上限回数で達しなかった場合は NG として明示します。

  歌詞に無い歌 (コーラス、ラララ) も同じモデルで区切られます (歌詞の事前が無いだけ)。

  学習済みの歌声採譜モデル (MIR-ST500 学習の CTC+CE モデル、ROSVOT、音素情報付き ICASSP 2023 モデル) も検証しましたが、
  いずれも歌詞タイミングを使う構成を下回ったため採用していません。f0 推定は RMVPE (Vocadito RPA 0.98) で十分で、
  PESTO / SwiftF0 / FCPE とのアンサンブルは効果が僅か (+0.4 pt) でした (詳細は開発メモ)。
- **コード進行** も Songle のものを使います。

## メロディの作り方と鳴らし方

聴いて確かめながら作り直した現在の既定は次のとおりです。

- **音節ごとに 1 音** (`analysis_sep.syllable_notes`): 歌詞の音節 (Songle の文字タイミング、無ければ歌から検出した音節) ごとに
  1 音を置き、歌詞の無い所には音を置かない。高さは音節の後ろ 7 割の、歌が安定している所に重みを置いた中央値
  (出だしのしゃくりを除く)。音節の中で 2 つ目の高さに 0.12 秒以上はっきり留まる (こぶし・メリスマ) ときだけ音を分ける。
  フレーズの終わりの音は歌の声が続く限り伸ばす。以前の方式は文字の中の揺れまで音符にしたり (千本桜で音節の約 2 倍の音符)、
  歌詞の無い所に音を置いたりして、「余計な音」「抜けた音」に聞こえた
- **歯切れ良く鳴らす** (`--melody-style crisp`): 音節の頭の音は拍の格子に揃えて立ち上げ直し、その直前で短く切る。
  音節の中で高さだけ変わる音はつなげる。ビブラート・音量の揺れは入れない
- **折り返しを抑えた矩形波** (`synth.pulse`, PolyBLEP): 素朴に ±1 を切り替える矩形波は、ナイキストを超える倍音が折り返して
  元の音と無関係な高さの成分 (倍音比 -20 dB) が混ざり、不協和音に聞こえていた (-35〜-41 dB に低減)
- **主旋律は上の声**: 歌ステムに同時に 2 声以上あるとき (ハモリ) は上の声を追う
- **ミックス**: メロディが伴奏より約 8 dB 大きくなるようにした (低い三角波ベースが耳に付いていた)

ほかの鳴らし方も `--melody-style` (画面の「メロディの鳴らし方」) で選べます:
`voice` / `voice_cont` (歌の声から直接), `follow` (音符の高さ + 歌の音量), `notes` (従来)。

## ファイル入力でも曲名を入れると Songle の情報を使います

ファイルをアップロードしたときに「曲名と作者名」(CLI では `--title`) を入れると、Songle で同じ曲を探します
(`chiptune/songle_match.py`)。曲名・各語で検索し、歌詞タイミングのある YouTube 版の音声を取得して、手元の音声と
音の立ち上がりの相互相関で照合します。同じ曲なら相関 0.8 前後 (別の曲では 0.1 前後) になり、頭の長さの違い (時間のずれ) も
10 ms 以内で求まるので、そのずれだけ補正した Songle の拍・歌詞タイミング・コードを使って、URL 入力と同じ方法で採譜します。
一致しなければ従来どおりファイルだけで採譜します。曲名は入力したときだけ Songle の検索と YouTube に送られます。

## Songle に無い曲・ファイル入力: 歌から音節の区切りを検出します

歌詞タイミングが無いと、f0 の変化と音量の谷だけでは音節 (文字) の区切りを取りこぼし、同じ高さで歌い直す箇所が 1 音につながって
リズムが崩れます (ボカロ曲は同音連打が多いので特に目立つ)。そこで、
- **音節オンセット検出器** (`chiptune/onset_model.py`, 約 90KB): 歌ステムのメルスペクトログラム + f0 + 音量から
  「ここで文字が始まる」確率を 10 ms ごとに出す小さな 1 次元 CNN。Songle / TextAlive の文字タイミングを教師に、
  ボカロ曲 23 曲で学習しています (`tools/train_onset.py`)。歌詞データは単語の中の文字が機械的に等分されていたり、
  漢字 1 文字に複数の音節が入っていたり、一部しか登録されていない曲があるので、そうした信用できない区間は教師から外しています。
- その確率を、歌詞の文字境界の代わりに楽譜モデルの事前として使います。音の始まりは確率の山で優遇、山を 1 音でまたぐのは不利、
  **同じ高さの歌い直しには山を要求** し、音高が変わる区切りは f0 の証拠だけでも置けるようにしています。
  拍節格子はビート検出から作ります。
- 70 ms 未満の細切れの音 (同じ高さの断片、音の移り目の経過音) は隣にまとめます (8bit ではブツブツ途切れて聞こえるため)。

従来の HMM 方式 (Tony 流) は、検出器が使えない環境 (torch が無い) でのフォールバックとして残っています。

## 仕組み

1. ffmpeg (同梱バイナリ) で音声を取り出す (YouTube URL のときは先に yt-dlp で音声トラックだけ取得)
2. ビート検出 → 16 分音符のグリッドを作り、打楽器のアタックに合わせて位置を補正
3. 採譜
   - **ボーカル分離モード (推奨)**: Meta の [Demucs](https://github.com/facebookresearch/demucs) で
     歌 / ドラム / ベース / その他に分離し、歌の音程を [RMVPE](https://arxiv.org/abs/2306.15412)
     (伴奏混じりの歌に強いピッチ推定器、初回に約 180MB の重みをダウンロード) で 10 ms ごとに追跡、
     楽譜モデル (半マルコフ Viterbi) で音符に分割する。音節の区切りは Songle の歌詞タイミング、無ければ歌から検出した音節の始まりを使う
     (検出器が使えない環境では Tony 流の HMM)。
     調に合わない短い音や、局所的な音域から大きく外れた孤立音 (ハモリ・伴奏の混入) は除く。元の歌のフレーズ (100 ms 未満の途切れは同一) に従い、
     フレーズ内の音は無音を挟まずつなぎ (同じ高さで歌い直す箇所は歌の音量の谷で切り直し、音の切り替えは音量のくぼみで区切る。ピッチスライドは既定 OFF)、フレーズの切れ目だけを休符にする (休符の前では切れ目を入れない)。ベース音源からベース、その他からコード、ドラム音源からドラムを取る。
     歌がほとんど無い曲は「その他」を basic-pitch で採譜した主旋律を使う
   - **高精度モード**: Spotify の [basic-pitch](https://github.com/spotify/basic-pitch) で曲全体を多声採譜し、
     一番高い音をメロディ、低い音をベース、出現ピッチクラスをコードに振り分け (伴奏の音が混ざりやすい)
   - **軽量モード**: HPSS で音程成分を取り出し、pyin でメロディ (中高域) とベース (低域) を追跡、chroma でコード推定
   - ドラムはどちらも打楽器成分のスペクトル変化をキック / スネア / ハイハットに分類
4. 伴奏を編曲し直す
   - **コード**: 伴奏 (その他 + ベース) の chroma にメロディの音を加え、調内の三和音を中心に拍ごとの Viterbi で進行を決める (変化には罰則、小節頭で変わりやすい)
   - **ベース**: コードの根音を土台に 8 分で刻む (検出したベース音がコード音ならそれを使う)。強い小節はオクターブ上を混ぜる
   - **ドラム**: ドラム音源の帯域別の立ち上がりを小節ごとに見て、4 つ打ち / 8 ビート / 16 ビート / ハーフタイムのパターンから選んで格子に打ち込む。テンポの倍/半分と格子の位相もキックから補正
   - **強弱**: 小節ごとの強度 (元曲の音量) でアルペジオの出し入れ・音量、ハイハットの間引きを決める。アルペジオはメロディの音域と重ならないオクターブに置く
5. NES 風シンセ (15bit LFSR ノイズ、4bit 階段三角波、矩形波) で演奏し、マスタリング (高域補正、ラウドネス -14 dB、ソフトリミッタ、フェードアウト) をして WAV / MP3 に書き出す

## メロディの評価

### 楽譜の分かっている評価曲 (正解の音符と比べる)

ボカロ曲は作者が打ち込んだ音符を合成音声に歌わせたもので、本来は正解の楽譜があります。それを再現するため
`tools/make_synth_gt.py` で、元曲の歌の声色・子音はそのままに、既知の楽譜 (文字ごとの音符) で歌い直させた曲を作ります
(WORLD ボコーダ。音の変わり目のポルタメントは実際のボカロ曲で測った「文字の頭と f0 の変わり目のずれ」に合わせ、
ビブラート・しゃくり・オーバーシュートも付ける)。元の伴奏と混ぜた曲を 8bit に変換し、`tools/eval_synth.py` で採点します。

| 指標 | 意味 |
| --- | --- |
| COnP | 始まり (±50 ms) と高さ (±50 cent) が合った音符の F 値 (mir_eval, 論文の標準) |
| TPA | 楽譜の音が鳴っている時間のうち、書き出した 8bit の WAV が正しい半音を鳴らしている割合 |

11 曲 (開発 6 + 検証 5) の結果 (8bit の WAV から測定):

| 入力 | COnP | TPA |
| --- | --- | --- |
| ファイル (最初の版) | 42.5 | 73.4% |
| ファイル (曲名なし, 現在) | 59.7 | 84.0% |
| ファイル + 曲名 (現在) | **84.0** | **89.1%** |
| YouTube URL (Songle あり, 現在) | **85.1** | **89.1%** |

`tools/analyze_synth_errors.py` で誤りの種類 (同じ高さの歌い直しの取りこぼし・始まりのずれ・高さの誤り・無音) を、
`tools/diag_synth.py` でそれがどの段階 (分離後の f0 / 音量のしきい値 / 後段) で生じたかを数えられます。
分離が完璧な場合 (`--oracle-vocal`) の上限は COnP 91 / TPA 96 で、残りの差は主に歌の分離の品質です
(BS-RoFormer も試しましたが、改善が小さく 1 曲 5 分かかるため採用していません)。

### 実際の曲 (歌の f0 と Songle の文字タイミングと比べる)

`tools/eval_8bit.py` は、曲を実際に 8bit に変換して WAV を書き出し、その 8bit のメロディ (矩形波) の音高と音の頭を
WAV から検出して、元の歌と比べます。正解には、元曲の歌ステムの f0 (RMVPE) と、Songle / TextAlive の文字タイミングを使います。

| 指標 | 意味 |
| --- | --- |
| mPAv | 音高がはっきりした文字 (歌が半音の中央に安定して留まる) のうち、2 つの f0 推定器 (RMVPE と FCPE) が同じ半音と判定したもの (= 正解が確かな文字) で、8bit が正しい半音を鳴らしている割合 |
| mPAc | 同じく、音高がはっきりした文字すべてで (f0 推定器自体の誤りも含む) |
| mPA | すべての文字で (しゃくり・ビブラートで正解が曖昧な文字も含む) |
| onF | 文字の始まりと 8bit の音の頭の一致 (±70 ms) の F 値 (リズムの再現) |
| RPA | 歌っている 10 ms フレームのうち、8bit の音が歌の音高 ±0.5 半音以内の割合 |

調整に使っていないボカロ曲 5 曲 (千本桜・初音ミクの消失・ロキ・ヴァンパイア・マトリョシカ) での結果。
すべて書き出した 8bit の WAV から音高と音の頭を検出して測っています。

| 入力 | 版 | mPAv | mPAc | mPA | onF | RPA |
| --- | --- | --- | --- | --- | --- | --- |
| ファイル (Songle 無し) | 最初の版 (HMM) | — | 93.2% | 79.5% | 51.2 | 73.7% |
| ファイル (Songle 無し) | 現在 | **99.3%** | **98.3%** | **84.5%** | **58.1** | **81.0%** |
| YouTube URL (Songle あり) | 現在 | **99.3%** | **98.4%** | **85.0%** | **71.6** | **78.8%** |

音高の決め方は、知覚される音高が f0 の安定した部分に引き寄せられる (Gockel et al. 2001, JASA) ことに合わせ、
歌が 60 ms 以上はっきり留まった半音は必ず鳴らし (100 ms 未満は音節の始まりがある場合だけ)、
音高が変わる境界は f0 が 2 音の中間を横切る時刻に合わせています (`chiptune/verify.py`, `notes.refine_boundaries`)。
評価で FCPE を使うには `uv pip install --python .venv/bin/python torchfcpe "numpy<2"` が必要です (変換自体には不要)。

```sh
.venv/bin/python tools/eval_8bit.py --heldout --no-songle   # ファイル入力相当で、検証用の 5 曲を評価
.venv/bin/python tools/eval_8bit.py greenlights             # 1 曲 (Songle あり)
```
曲は `~/.cache/8bit_music/testsongs/` に YouTube から取得して置きます (ID は `tools/mm_common.py`)。

## 注意

- ボーカル分離モードは Apple Silicon の GPU (MPS) を使い、4 分の曲で 1〜2 分ほどかかります。高精度モードは 15 秒ほど、軽量モードは数秒です。
- 分離モードでもラップや細かいビブラートの歌は音が細切れになりがちです。うまくいかないときはモードや音色を変えて試してください。
- 初回セットアップでは PyTorch + Demucs (約 650MB) と、初回変換時に分離モデル (約 80MB) をダウンロードします。
- YouTube の URL は 20 分以内の動画に対応しています。yt-dlp は JavaScript 実行環境として deno (推奨) か node 22 以上を探します。無くても取得はできますが、警告が出て一部の形式が取れないことがあります (`brew install deno` で解消)。YouTube 側の仕様変更でダウンロードできなくなったときは `uv pip install --python .venv/bin/python -U yt-dlp` で yt-dlp を更新してください。
- 変換に使う曲の著作権や YouTube の利用規約にはご注意ください (個人で楽しむ範囲で)。
