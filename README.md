# 8bit Music Converter

mp4 (や mp3 / wav / m4a) か **YouTube の URL** を入れると、その曲を **ファミコン風の 8bit チップチューン** に作り直してダウンロードできるローカル Web アプリです。

元の音声にエフェクトを掛けるのではなく、曲を「耳コピ」してファミコンの 4 チャンネル
(矩形波 ×2 / 三角波 / ノイズ) で演奏し直す方式なので、本当にゲーム音楽っぽいピコピコ感が出ます。

## 使い方

```sh
./setup.sh      # 初回だけ (Python 3.12 の仮想環境を作って依存を入れる。数分かかります)
./run.sh        # サーバー起動 → http://localhost:35607 をブラウザで開く  (PORT=xxxx ./run.sh で変更可)
```

ブラウザ画面に mp4 をドロップするか YouTube の URL を貼り付けて「8bit に変換する」を押すと、変換後に試聴プレーヤーとダウンロードボタンが出ます。

コマンドラインでも使えます:

```sh
.venv/bin/python convert.py 曲.mp4              # → 曲_8bit.wav
.venv/bin/python convert.py 曲.mp4 --mp3 --duty 0.25 --arp-speed 2
.venv/bin/python convert.py "https://www.youtube.com/watch?v=XXXX"   # → <動画タイトル>_8bit.wav
.venv/bin/python convert.py 曲.mp4 --midi        # → 曲_8bit.mid (採譜結果)
.venv/bin/python convert.py 曲_8bit.mid          # 直した MIDI をそのまま 8bit 演奏
.venv/bin/python convert.py 曲.mp4 --sensitivity 0.6 --tempo-mult 2 --octave 1 --no-fill
```

ポートは 35607 (16 進で 8B17 = "8BIT") にしてあります。他と被る場合は `PORT=12345 ./run.sh` のように変えられます。

## GitHub Pages から使う

UI は静的ファイルなので GitHub Pages で配信しています: https://hueno-ttic.github.io/8bit_music/
ただし変換そのもの (音源分離・採譜・演奏) は Python サーバーが必要で、GitHub Pages では動きません。
Pages の UI から使うときは、手元で

```bash
./setup.sh && ./run.sh
```

を起動しておき、ページ上部の「変換サーバーの URL」に `http://localhost:35607` (既定) を入れてください。
接続できると「✓ サーバーに接続できました」と出ます。
Chrome (138 以降) は公開サイトから localhost への接続時に「ローカルネットワークへのアクセス」の許可ダイアログを出すので「許可」を押してください
(拒否してしまった場合はアドレスバー左のサイト情報から許可し直して再読み込み)。Safari で弾かれる場合は http://localhost:35607 を直接開いてください。
サーバー側は Pages のオリジン (https://hueno-ttic.github.io) と localhost からの呼び出しだけを受け付けます。
`main` に push すると `.github/workflows/pages.yml` が `static/` とサンプル曲を Pages に配信します。

## オプション

| 項目 | 説明 |
| --- | --- |
| 採譜モード | `auto` は使える中で最良のモード (ボーカル分離 > 高精度 > 軽量) を選ぶ |
| メロディの音色 | 矩形波のデューティ比 50% / 25% / 12.5% |
| コードのアルペジオ | 検出したコードを 16 分 (または 32 分) で回すお馴染みの伴奏 |
| 三角波ベース / ノイズドラム | チャンネルごとの ON/OFF |
| 8bit 量子化 | 出力を 8bit 相当に丸めてザラつきを足す |
| メロディにエコー / オクターブ | 8 分音符遅れのエコー (歌の細かい動きが二重に聞こえるので既定 OFF) と、メロディのオクターブ移動 |
| 歌の拾いやすさ | 分離モードで歌と判定する確信度のしきい値 (上げると拾いやすく、誤検出も増える) |
| テンポ | ビート検出が実際の半分になった速い曲は「倍にする」 (自動判定もあり) |
| 間奏をリード楽器で埋める | 歌が 2 小節以上無い区間を伴奏の主旋律で埋めるか (誤った音が出やすいので既定 OFF) |
| 調に合わない音を補正 | 推定した調から外れる短い音を半音寄せる |
| リズムを格子に整える | メロディの始まり・長さを 32 分音符の格子に量子化し、1 セルの揺れの吸収・オクターブ補正・子音による短い隙間 (2 セル未満) の補完・拍頭のアクセント付けを行う。それ以上の隙間は休符として残す (既定 ON) |
| 歌の無いイントロを省く | 最初の歌の 1 拍前から出力を始める (既定 ON)。歌の無いイントロで主旋律を捏造しない |
| 出力形式 MIDI | 採譜結果を MIDI で出す。DAW で直した .mid をそのまま入力に戻すと、その通りに演奏する |

## YouTube の URL を使うと Songle / TextAlive の情報を使います

入力が YouTube の URL で、その曲が [Songle](https://songle.jp) に登録されている場合 (マジカルミライの曲は概ね登録済み)、
- **歌詞の文字ごとの発声タイミング** (TextAlive で使われている人手修正済みのデータ) と **拍** を使い、
  「楽譜モデル + F0 モデル」(Nishikimi, Nakamura, Goto ら, ISMIR 2017 / IEEE TASLP 2020 の考え方) でメロディを推定します
  (`chiptune/score_model.py`)。歌の f0 を規則で刻むのではなく、
  - 楽譜モデル: 調 (音階) に沿った音高の事前、音程の事前 (小さい音程ほど確からしい)、拍節格子 (Songle の拍から 32 分) 上の
    音の始まり (拍頭 > 8 分裏 > 16 分裏)、音価の分布、歌詞の文字境界 (文字の頭で音を切り直し、文字の途中では切らない)
  - F0 モデル: 音符列から歌の f0 が生成される過程を Cauchy 分布で表す (ビブラート・しゃくりに頑健)。音の頭の移行区間は
    前後の音高の混合として扱う
  を合わせた確率モデルの下で、最も確からしい音符列を半マルコフ Viterbi で一括して決めます。「隣のキーを押したような」半音ずれや
  調外れの音が規則ベースより大きく減ります (グリーンライツ: 調外 33 → 9 音、外れ音 0.4%)。
  推定後に、分離の残渣によるごみ音を落とし、歌のフレーズに従って音をつなぎます (f0 が続く間だけ伸ばす)。
  文字の始まりは子音の頭なので、音高が変わる文字では f0 が前後の音高の中間を横切る時刻に音の頭を移します。
  伴奏の格子 (テンポ・16 分セル・小節頭) も Songle の拍から作り、メロディと同じ格子に乗せます。

- **自己検証と修正の繰り返し** (`chiptune/verify.py`): 採譜した音符列を歌の f0 と照合し、
  「外れ」(音の中央 50% の f0 が音符の高さから 1 半音超ずれ、かつその高さが音の中のどこにも歌われていない音) と
  「併合」(1 音の中に別の高さの安定区間がある音) を見つけて直し、外れが 0.1% 以内になるまで最大 5 回繰り返します。
  何回修正したか、目標に達したかは UI の結果欄 (「自己検証 OK / NG — 修正 N 回」) と CLI のログに表示され、
  上限回数で達しなかった場合は NG として明示します。

  歌詞に無い歌 (コーラス、ラララ) も同じモデルで区切られます (歌詞の事前が無いだけ)。
  Songle に拍が無い曲やファイル入力では、従来の HMM 方式 (Tony 流) で区切ります。Vocadito (拍情報なし) では HMM の方が良いためです。

  学習済みの歌声採譜モデル (MIR-ST500 学習の CTC+CE モデル、ROSVOT、音素情報付き ICASSP 2023 モデル) も検証しましたが、
  いずれも歌詞タイミングを使う構成を下回ったため採用していません。f0 推定は RMVPE (Vocadito RPA 0.98) で十分で、
  PESTO / SwiftF0 / FCPE とのアンサンブルは効果が僅か (+0.4 pt) でした (詳細は開発メモ)。
- **コード進行** も Songle のものを使います。
登録が無い曲やファイルのアップロードでは、従来どおり解析だけで採譜します。

## 仕組み

1. ffmpeg (同梱バイナリ) で音声を取り出す (YouTube URL のときは先に yt-dlp で音声トラックだけ取得)
2. ビート検出 → 16 分音符のグリッドを作り、打楽器のアタックに合わせて位置を補正
3. 採譜
   - **ボーカル分離モード (推奨)**: Meta の [Demucs](https://github.com/facebookresearch/demucs) で
     歌 / ドラム / ベース / その他に分離し、歌の音程を [RMVPE](https://arxiv.org/abs/2306.15412)
     (伴奏混じりの歌に強いピッチ推定器、初回に約 180MB の重みをダウンロード) で 10 ms ごとに追跡、
     Tony 流の HMM (Viterbi) で音符に分割する。格子に丸めないので速い歌でも音が潰れない。
     調に合わない短い音や、局所的な音域から大きく外れた孤立音 (ハモリ・伴奏の混入) は除く。元の歌のフレーズ (100 ms 未満の途切れは同一) に従い、
     フレーズ内の音は無音を挟まずつなぎ (同じ高さで歌い直す箇所は歌の音量の谷で切り直し、音の切り替えは音量のくぼみで区切る。ピッチスライドは既定 OFF)、フレーズの切れ目だけを休符にする (休符の前では切れ目を入れない)。ベース音源からベース、その他からコード、ドラム音源からドラムを取る。
     歌がほとんど無い曲は「その他」を basic-pitch で採譜した主旋律を使う
   - **高精度モード**: Spotify の [basic-pitch](https://github.com/spotify/basic-pitch) で曲全体を多声採譜し、
     一番高い音をメロディ、低い音をベース、出現ピッチクラスをコードに振り分け (伴奏の音が混ざりやすい)
   - **軽量モード**: HPSS で音程成分を取り出し、pyin でメロディ (中高域) とベース (低域) を追跡、chroma でコード推定
   - ドラムはどちらも打楽器成分のスペクトル変化をキック / スネア / ハイハットに分類
4. 伴奏を編曲し直す
   - **コード**: 伴奏 (その他 + ベース) の chroma にメロディの音を加え、調内の三和音を中心に拍ごとの Viterbi で進行を決める (変化には罰則、小節頭で変わりやすい)
   - **ベース**: コードの根音を土台に 8 分で刻む (検出したベース音がコード音ならそれを使う)。強い小節はオクターブ上を混ぜる
   - **ドラム**: ドラム音源の帯域別の立ち上がりを小節ごとに見て、4 つ打ち / 8 ビート / 16 ビート / ハーフタイムのパターンから選んで格子に打ち込む。テンポの倍/半分と格子の位相もキックから補正
   - **強弱**: 小節ごとの強度 (元曲の音量) でアルペジオの出し入れ・音量、ハイハットの間引きを決める。アルペジオはメロディの音域と重ならないオクターブに置く
5. NES 風シンセ (15bit LFSR ノイズ、4bit 階段三角波、矩形波) で演奏し、マスタリング (高域補正、ラウドネス -14 dB、ソフトリミッタ、フェードアウト) をして WAV / MP3 に書き出す

## 構成

```
app.py              FastAPI サーバー (ブラウザ UI は static/index.html)
convert.py          コマンドライン版
chiptune/
  audio_io.py       ffmpeg での読み書き
  youtube.py        yt-dlp で URL から音声を取得
  analysis.py       軽量 DSP 採譜 + グリッド + ドラム検出
  analysis_ml.py    basic-pitch を使った高精度採譜
  separation.py     Demucs による音源分離 (結果は ~/.cache/8bit_music/stems にキャッシュ)
  analysis_sep.py   分離したステムごとの採譜 (ボーカル分離モード)
  midi_io.py        採譜結果の MIDI 書き出し / 読み込み
  pitch.py          RMVPE による歌の f0 推定 (重みは ~/.cache/8bit_music に保存)
  rmvpe_model.py    RMVPE の推論コード (RVC-Project より同梱, MIT)
  notes.py          f0 → 音符の HMM 分割・フレーズ接続・シラブル分割 (歌詞・拍が無いとき)
  score_model.py    楽譜モデル + F0 モデルによる音符推定 (半マルコフ Viterbi、歌詞・拍があるとき)
  melody_clean.py   推定した音符列の後処理 (ごみ音の除去など)
  harmony.py        調とコード進行の推定 (Viterbi)
  rhythm.py         テンポ補正・小節頭・ドラムパターン
  arrange.py        小節ごとの強度・ベースライン・アルペジオ音域
  master.py         マスタリング
  songle.py         Songle / TextAlive の歌詞タイミング・拍・コードの取得 (~/.cache/8bit_music/songle にキャッシュ)
  synth.py          ファミコン風 4ch シンセ
  convert.py        変換パイプライン
samples/            テスト用の合成曲と変換結果
```

## 注意

- ボーカル分離モードは Apple Silicon の GPU (MPS) を使い、4 分の曲で 1〜2 分ほどかかります。高精度モードは 15 秒ほど、軽量モードは数秒です。
- 分離モードでもラップや細かいビブラートの歌は音が細切れになりがちです。うまくいかないときはモードや音色を変えて試してください。
- 初回セットアップでは PyTorch + Demucs (約 650MB) と、初回変換時に分離モデル (約 80MB) をダウンロードします。
- YouTube の URL は 20 分以内の動画に対応しています。yt-dlp は JavaScript 実行環境として deno (推奨) か node 22 以上を探します。無くても取得はできますが、警告が出て一部の形式が取れないことがあります (`brew install deno` で解消)。YouTube 側の仕様変更でダウンロードできなくなったときは `uv pip install --python .venv/bin/python -U yt-dlp` で yt-dlp を更新してください。
- 変換に使う曲の著作権や YouTube の利用規約にはご注意ください (個人で楽しむ範囲で)。
